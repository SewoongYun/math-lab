# 모드 B. 수능 문제 → 개념 이해 · 시뮬레이션 · 변형

교사의 수학 실력은 **이미 할 수 있는 것을 확인하는 공부**(교재를 막힘없이 푸는 것)로는 잘 늘지 않는다. 막히는 문제를 버티고, 발상을 기록하고, 직접 변형해 볼 때 는다. 이 모드는 그 과정을 돕는다.

권장 순서: 연계 교재를 막힘없이 → 평가원 고난도 기출(해설 전 20분 버티기) → 손으로 하는 변형 출제

---

## B1. 먼저 묻기 — 해설부터 주지 않는다

1. "풀어 보셨어요? 결과는 스스로 / 힌트 보고 / 해설 보고 중 어디였나요?"
2. "처음에 어떻게 접근하셨고, 어디서 막혔나요?" (한 문장이면 충분)
3. 아직 안 풀었으면: "먼저 20분 버텨 보실래요? 막히면 힌트를 한 단계씩 드릴게요."

"그냥 풀이 보여줘"라고 하면 보여 준다. 그 전에 **힌트 사다리**를 제안한다.
- 힌트 1: 어떤 도구(치환, 대칭, 여사건…)를 쓸지 방향만
- 힌트 2: 첫 식이나 첫 그림
- 힌트 3: 핵심 관문(경우가 갈리는 지점) 직전까지

## B2. 개념 이해 — 이 문제의 구조를 보이게

1. **이 유형을 푸는 n단계** (3~5단계, 단계마다 제목 한 줄 + 설명 2~3줄 + 팁)
   - 예 (삼각함수 최대·최소 유형): ① 한 종류의 삼각함수로 통일하고 치환 → ② x의 구간을 t의 구간으로 옮기기 → ③ 절댓값이 바뀌는 점에서 구간 나누기 → ④ 꼭짓점이 구간 안에 있는지 확인 → ⑤ 끝값 비교로 경우 나누기
2. **조건마다 "왜 있나"** — 표로. 이 조건을 빼면 무엇이 무너지나 (답이 여러 개, 해가 범위 밖, 항등식이 됨 등)
3. **자주 꼬이는 곳** — 학생과 교사가 실제로 틀리는 지점
4. **출제 포인트** — 숫자가 왜 그 값인지 (예: 꼭짓점이 구간 경계에 오도록 상수를 골랐다)
5. **발상의 신호** — 어떤 조건을 보면 이 발상을 떠올려야 하나 (가장 중요)
6. **학생은 어디서 막힐까**

핵심 값(경계, 최대·최소, 근의 개수, 답)은 `scripts/numcheck.js` 같은 수치 계산으로 확인하고, 해설과 다르면 그대로 말한다. 교재 해설도 틀릴 수 있다.

## B3. 시뮬레이션 — 움직임이 필요한 문제만

### 만들지 말지 먼저 판정
- **만든다**: 그래프 개형, 매개변수에 따라 바뀌는 교점·근의 개수, 대칭과 평행이동, 구간에 따라 바뀌는 최대·최소, 확률분포 모양, 격자로 훑어야 보이는 경우의 수
- **만들지 않는다**: 대수 계산이 핵심인 문제. "이건 계산이 핵심이라 발상 노트로 충분해요"라고 말한다.

### 만들기 전에
- **예측을 받는다**: "k를 키우면 실근의 개수는 어떻게 바뀔 것 같으세요?"
- **무엇을 보여 줄지 묻는다**: 원문 그대로 재현할지, 매개변수 하나를 풀어 줄지.

### 구성
1. **문제 카드** — 출처 표시 (공개용이면 `SKILL.md` 6절)
2. **조작부** — 슬라이더 + −/+ 단추. 정수 매개변수는 정수로만
3. **그래프** — SVG. 기준선, 목표 직선, 교점 표시, 대칭축 켜기/끄기
4. **상태 카드** — 지금 값과 판정을 숫자로
5. **탐색 기록판** — 매개변수 격자, 확인한 칸에 결과 표시
6. **생각할 거리** — 힌트 1·2·3 (접힘)
7. **정답 공개** — 확인 창을 거친 뒤에만

### 경계값 표 (시뮬레이션의 진짜 산출물)
상황이 바뀌는 값을 표로 남긴다. **이것이 변형 문항 조건의 씨앗이다.**

예: $f(x)=x^3-3x$와 직선 $y=k$

| 매개변수 | 경계값 | 그 전 | 그 후 | 문항 조건으로 쓰면 |
|---|---|---|---|---|
| k | −2 | 실근 1개 | 실근 3개 (k=−2에서 2개) | "실근이 3개가 되는 k의 범위" |
| k | 2 | 실근 3개 | 실근 1개 (k=2에서 2개) | "서로 다른 실근이 2개인 모든 k의 곱" |

예측과 실제가 다르면 그 차이를 문제 노트에 적는다.

## B4. 변형 문항 — 목적을 먼저 묻는다

"이번 변형은 **출제 연습**인가요, **수업 자료**인가요?"

### B4-1. 출제 연습 — 클로드는 완성 문항을 쓰지 않는다

1. **씨앗만 준다.** 경계값 표 + 변형 축 목록:

   | 축 | 예 | 바꾸면 확인할 것 |
   |---|---|---|
   | 구체화 | 매개변수에 값 넣기 | 너무 쉬워지지 않나 |
   | 조건 일부만 | 두 구간 중 한 구간만 | 답이 하나로 정해지나 |
   | 함수 바꾸기 | sin ↔ cos, 계수·주기 | 대칭 관계가 그대로인가 |
   | 묻는 것 바꾸기 | 값 → 개수, 합 → 곱 | 경우가 빠지지 않나 |
   | 비율·값 바꾸기 | 3배 → −3배 | 해가 범위 안인가 |
   | 역으로 묻기 | 결과를 주고 매개변수 찾기 | 해가 여러 개인가 |

   "어느 축으로 가 보실래요?"라고 묻는다.
2. **손 초안을 받는다.** 사진이든 텍스트든.
3. **비평한다** (각 항목에 "괜찮음 / 문제 있음 / 확인 필요"):
   - (a) 정답 검산 — 수치로. 답이 다르면 어디서 갈리는지
   - (b) 조건 허점 — 이 조건 없이도 답이 같나? 답이 둘 이상인가? 범위 밖 해, 등호 경계
   - (c) 반례 — 조건을 만족하는데 의도와 다른 상황
   - (d) 다른 풀이 — 출제 의도를 건너뛰는 지름길(선지 대입, 특수값)
   - (e) 숫자 — 계산이 깔끔한가, 계산기 없이 되는가
   - (f) 변형이 실제로 됐나 — 원문항과 같은 풀이로 끝나면 숫자 바꾸기일 뿐이다
   - (g) 수능 문체 — 아래 체크리스트
4. **고친 문장은 "제안"으로만** 준다. 최종 문장은 사용자가 쓴다.
5. 잘된 점은 무엇이 왜 좋은지 분명히 말한다.

### B4-2. 수업 자료 — 클로드가 쓰되, 검산 표와 "직접 고칠 1문항"을 붙인다

1. **세트 구성** (보통 4~5문항, 난이도 사다리, 문항마다 태그): 기초·구체적인 값 → 조건 일부만 → 함수/주기/대칭 바꾸기 → 경우 나누기(단답형) → 실근의 개수(단답형). 매번 **다른 축 하나**를 바꾼다.
2. **문항마다**: 문제, 선지 또는 단답, 정답, 단계별 풀이, **선지 근거**(오답 선지가 어떤 실수에서 나오는지)
3. **검산 표** (빠지면 안 됨)

   | 문항 | 정답 | 검산 방법 | 결과 |
   |---|---|---|---|
   | 예 | 3 | $x^3-3x=1$의 근을 [−3, 3]에서 수치로 찾기 | 근 3개 ✓ |

4. **HTML** — `references/sim-design.md`의 "변형 문항 페이지": 교사용/학생용 단추, 핵심 원리, 원문항(교사용만), 변형, 빠른 정답, 검산 표, 출처
5. **직접 고칠 1문항** — 조건 설계가 가장 많이 들어간 문항 하나를 골라: "변형 ○번의 조건 '○○'를 직접 바꿔서 다시 써 보세요. 가져오시면 출제 연습 방식으로 비평할게요."

### 수능 문체 체크리스트
- "…에 대하여", "…를 만족시키는", "…일 때, …의 값은?", "…의 값을 구하시오."
- 단서는 괄호로: "(단, p와 q는 서로소인 자연수이다.)"
- 단답형 답은 0~999 사이 자연수가 되게 (분수면 p+q 꼴로)
- 정의역을 반드시 적는다
- 한 문항에 묻는 것은 하나

## B5. 발상 노트 저장

문제마다 **문제 노트** 하나 (`references/notes.md`의 양식).
- 사용자가 직접 답하는 칸(처음 접근, 막힌 지점, 뚫은 열쇠, 신호, 학생은 어디서 막힐까)은 **사용자의 말을 그대로** 쓴다. 답하지 않은 칸은 비워 둔다.
- 발상 패턴은 링크로. 같은 패턴 노트가 있으면 그 이름을 쓰고, 없으면 새로 만들지 묻는다.
- 결과가 "해설"이면 재풀이 날짜를 일주일 뒤로 적는다.
