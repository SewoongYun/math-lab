# 모드 A. 책 → 실험실

수학책은 줄글이라 학생들이 읽다가 쉽게 포기한다. 이 모드는 책의 한 문장을 학생이 손으로 움직여 볼 수 있는 실험실로 바꾼다. 네 가지 원칙이 뼈대다.

1. **짧게 묻고 시작하기** — 사진 한 장과 질문 한 줄로 개념부터 확인
2. **기존 자료를 기준으로** — 이미 만든 실험실이 있으면 그 구조와 디자인을 이어 간다
3. **불편한 점을 구체적으로** — "가독성", "용어 정리"처럼 콕 집어 고친다
4. **내용 검증은 교사 몫** — 클로드는 검증할 곳을 표시해 준다

---

## A1. 문장 확인

받아야 할 것: **책 이름, 쪽수, 밑줄 문장**. 사진이면 읽은 문장을 그대로 보여 주며 맞는지 확인한다.

- `config.md`에 책 사이트 데이터 파일이 있으면 같은 개념의 실험실이 이미 있는지 확인한다. 있으면 "새로 만들까요, 그걸 넓힐까요?"라고 묻는다.
- 노트 폴더에 `책 실험실/<책 이름>.md`가 있으면 읽는다. 지난번 손계산과 질문이 거기 있다.
- 책 정보(저자, 번역자, 출판사, 목차)는 사용자가 준 것만 쓰고 지어내지 않는다.

## A2. 문장 해부 (대화로, 짧게)

| 항목 | 묻는 것 |
|---|---|
| **숨은 수학** | 이 문장 뒤의 개념은? 교육과정의 어느 단원과 이어지나? (예: 그림 도표의 크기 → 닮음비, 넓이 k², 부피 k³) |
| **학생이 지나치는 이유** | 낯선 용어, 줄글, 숫자가 없음, 직관과 반대 등 |
| **책의 가정 의심하기** | 저자가 깔고 있는 가정, 숫자의 출처, 지금 시점에서 달라진 것. 수학 밖 내용은 "교사 확인 필요" |
| **보이게 할 것 하나** | 학생이 화면에서 "아!" 해야 할 장면 하나. 실험실의 중심이 된다 |

그리고 묻는다: "학생에게 무엇이 보이게 하고 싶으세요?" (클로드의 제안은 하나만 붙인다)

## A3. 손계산 하나 + 예측

- 그 장의 핵심 계산을 **숫자가 정해진 문제 하나**로 낸다. 계산기 없이 10분 안에 풀리게.
  - 예: 주성분 분석 → "점 (1,2), (2,3), (3,5)의 공분산 행렬을 손으로 구해 보세요."
  - 예: 물가지수 → "두 물건 값이 각각 ×0.5, ×2가 되었다. 기준 시점=100일 때 산술평균 지수와 기하평균 지수는?"
- 답을 받으면 맞는지 확인하고, 틀렸으면 **어디서 갈렸는지** 짚는다.
- 이 계산은 실험실의 **손계산 단계에 그대로** 쓴다.
- "건너뛰기"면 건너뛰고 기록에 `손계산: 건너뜀`.
- 예측: "슬라이더를 끝까지 올리면 ○○는 어떻게 될까요?" 한 줄 받아 두고, 스케치 뒤에 맞았는지 같이 본다.

## A4. 스케치 (개념 확인용)

- 완성도가 아니라 **개념이 맞게 잡혔는지**만 보는 작은 위젯. 슬라이더 1~3개 + 그림 하나 + 판정 문구 한 줄.
- "이 방향 맞아요"가 나오면 A5로. 아니면 무엇이 다른지 묻고 고친다.

## A5. 실험실

`references/sim-design.md`의 **책 실험실 디자인**을 쓴다. 같은 책의 실험실이 이미 있으면 그 파일을 읽고 구조와 디자인을 맞춘다.

| 단계 | 이름 | 내용 |
|---|---|---|
| STEP 1 | **예상** | 상황 소개(짧은 인용 + 쪽수), 꼭 필요한 개념 카드(뜻·예시), 학생이 감으로 고르는 예상 |
| STEP 2~3 | **조작 / 실험** | 슬라이더·버튼으로 바꿔 보기, 바로가기 버튼, 기록 표. 화면 아래에 "STEP 1 내 예상: ○○" |
| STEP n−1 | **손계산** | A3의 숫자로 빈칸 채우기 → 채점 → "풀이 보기". "더 해 보기" 1~2개 |
| STEP n | **정리** | 오늘의 정리(한 문장 + 핵심 표), STEP 1 예상 다시 보기, **생각할 거리 Q1~Q5**, **나만의 질문 1개** |

### 숫자 설계
- 겉은 슬라이더지만 뒤에는 숫자 설계가 있다. **나누어떨어지는 수**를 골라 손계산 단계가 수업에서 돌아가게 한다.
- 가능하면 책의 다음 문단이나 다른 실험실의 숫자와 이어지게 맞춘다.

### 생각할 거리 Q1~Q5
다섯 개를 같은 종류로 만들지 않는다.
- **책 속 장면 다시 보기**: 저자는 이 숫자로 무엇을 노렸나?
- **다른 실험실과 비교**: 무엇이 같고 다른가?
- **지금 세상**: 뉴스·AI·경제에 같은 원리가 있나?
- **질문 만들기 (꼭 하나)**: 답을 구하는 게 아니라 "이런 숫자를 보면 무엇을 먼저 확인해야 하나?"를 묻는다
- **평가로 쓸 수 있는 것**: 서술형·논술형으로 바로 쓸 수 있는 질문 하나를 표시한다

### 문장
- 학생 화면은 짧은 문장, "~다 / ~해 보자" 평서체. 긴 문단 대신 짧은 문장 + 인용 상자.
- 용어는 처음 나올 때 카드로 (뜻 · 예시 · 이 책에서는).
- 책 인용은 한두 문장으로 짧게, 쪽수를 붙인다.

## A6. 다듬기

- 피드백이 막연하면("더 좋게") 무엇이 불편한지 되묻는다: 가독성? 용어? 단계 수? 숫자?
- **크게 고치기 전에 지금 버전 사본을 남긴다** (`… (v1).html`). 수정 전 자료도 연수 재료가 된다.
- 고친 뒤 "무엇이 바뀌었나" 표(항목 / 전 / 후)를 짧게 준다.

## A7. 저장

- HTML: `config.md`의 책 실험실 폴더. 파일 이름은 `<차시> <제목>.html` 또는 `<제목>.html`.
- 책 사이트 데이터 파일이 설정돼 있으면 항목 초안을 보여 준다 (파일은 고치지 않는다):

```js
{
  id: "영문-하이픈-id",
  title: "실험실 제목",
  file: "programs/<파일 이름>.html",
  type: "실험",            // 카드뉴스 / 단계 활동 / 읽기 자료 / 실험 / 시뮬레이터
  session: "",             // 차시 (없으면 "")
  pages: "○~○쪽",
  summary: "한 줄 소개",
  concepts: ["개념1", "개념2"]
}
```

- 실제 사이트 반영·커밋·배포는 사용자가 요청할 때만 한다.
- 노트: `references/notes.md`의 "책 실험실 기록"에 한 줄 추가.
